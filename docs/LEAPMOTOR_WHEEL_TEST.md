## 开关和诊断位置

- 设置 → 车辆 → 零跑方向盘控制 → 接收零跑方向盘按键。
- 设置 → 诊断 → 零跑方向盘诊断 → 记录方向盘诊断（默认关闭）。

开关立即生效，不要求重新连接。存在 CarPlay 连接任务时注册监听；没有活动的媒体控制会话或控制器已关闭时只记录按键，不转发控制。主屏幕流单独拆除、音频及控制会话仍保留时，按键继续转发，诊断仍显示已连接。连接任务结束或关闭开关时注销接收器。旧连接结束不会注销新连接的接收器。

诊断卡片每秒刷新显示。记录开关关闭时，不新增方控事件、计数、媒体上报诊断或本模块的 Logcat 日志，方向盘转发和媒体来源上报照常运行。开启记录会清空上一轮缓存并开始新一轮采集；关闭后保留已采集记录供手动导出，界面提示记录已关闭。

记录内容包括媒体状态上报结果和次数、收到的广播数、提交的指令数，以及最近 6 条按键记录。每条记录包含时间、`value`、`playMediaType`、识别操作和处理结果。上报“已发送”表示最近一次发送 API 未报错，不代表原车已接收，也不代表此时仍拥有媒体来源。

“清空记录”清空按键和媒体上报诊断，监听及媒体上报继续运行。按键历史仅在内存中保留最近 20 条，进程退出后不保留；不会自动新增日志文件。现有日志系统和手动保存的报告不受此开关删除。“保存诊断报告”和新版手机网页下载入口均包含已采集的零跑诊断。

## 自动上报与生命周期

通过 `com.leapmotor.transfer.MEDIA.INFO` 发送字符串 extra `info`，JSON 为 `type=music`，`data` 包含媒体类型 14、歌曲名称、歌手以及状态 1（播放）或 0（暂停）。该状态来自与 Android MediaSession 相同的 iPhone 元数据／音频状态。歌曲和播放状态不变时不重复发送，进度更新不触发上报。

未永久失去音频焦点时，开启开关会立即上报已经取得的当前媒体状态。暂停、恢复、切歌会更新上报。关闭开关、断开连接或替换控制器时，若此前上报了播放状态，则发送一次暂停状态并清理旧发布状态。旧控制器的回调不影响新连接。上报异常会显示失败；后续状态回调可重试。

永久失去音频焦点后，若此前上报了播放状态，先发送一次状态 0，再停止媒体上报。后续歌曲及进度继续保留在 Android MediaSession 和内部缓存中，但不会因后台切歌或重新打开零跑开关而发送状态 1。重新收到有效焦点 GAIN，或 iPhone 重新播放并成功申请焦点后，发送最新缓存状态；歌曲未变化也能重新取得来源 14。瞬时丢焦点和可降音量的语音打断沿用原有行为，不撤销媒体来源。旧控制器、已替换焦点请求及被后续焦点事件覆盖的排队 GAIN 均不能重新取得来源。

媒体音频路由继续使用设置值 0，实车对应音乐流 3 和 `BUS00_MEDIA`。媒体来源 14 不用于设置 Android 音频流，也不需要写 `carlink_connect_state`。

## 保留原车上下栏

在连接 CarPlay 前，关闭“显示”中的“隐藏状态栏”和“隐藏导航栏”，并取消应用管家针对 DiPlay 的沉浸规则。上下栏常驻后，应用统一处理 WindowInsets，视频、触摸层、设置菜单和安全区域编辑器使用同一个可用区域。已有窗口或父容器预留的空间不会再次扣除。

本车实测主屏为 1920×1080，顶部栏 80 px，底栏 120 px。目标区域为屏幕坐标 `[0,80]–[1920,960]`，即 1920×880。代码读取系统 Insets，不把这两个栏高硬编码到其他设备。TextureView 和 SurfaceView 使用同样的布局；CarPlay 协商与触摸映射继续读取实际视频 View 尺寸。改变隐藏栏设置时沿用原有重新协商行为，建议先设置再连接。

系统键盘弹出时，仅缩短设置菜单的滚动区域，安全区编辑器仅上移“取消”和“保存”按钮。视频、触摸层和安全区编辑画布保持原尺寸。键盘 Insets 使用根布局扣除系统栏后的剩余高度，避免重复扣除底部 Dock；菜单重建或从安全区编辑器返回时重新请求 Insets。

## 广播与映射

Action：`com.leapmotor.action.METER.CTRL`。

| 字符串 extra `value` | CarPlay 操作 |
| --- | --- |
| `1` | 上一首 |
| `2` | 下一首 |
| `3` | 播放／暂停切换 |
| `0`、其他值、缺少参数或参数类型错误 | 记录并忽略 |

整数 extra `playMediaType` 会被记录，仅类型 14 的有效媒体按键转发给 CarPlay，其他来源只记录并忽略，避免控制原车其他媒体时同时操作 iPhone。若正在播放车机视频，按键交给现有视频控制接口，诊断结果单独标注为视频播放器处理。

监听来自外部应用／系统的广播：Android 13+ 使用 `RECEIVER_EXPORTED`，较早版本使用动态广播接收器。本车已确认原厂多媒体进程向 DiPlay 投递类型 14 的实体广播。

`SUBMITTED` / “已提交”只说明 CarPlay 发送请求已进入队列，不证明 iPhone 已接收或歌曲已切换。`NOT_CONNECTED` 表示当时没有活动的媒体控制会话或控制器已关闭；`FAILED` 表示请求未提交；`IGNORED` 表示参数不属于支持的媒体操作；`VIDEO_PLAYER` 表示车机视频播放器处理了操作。

收到广播的计数包含 `value=0` 等被忽略事件，所以它不一定等于方向盘按下次数。

## 车上测试和反馈

1. 从本仓库 Release 下载 APK，安装并打开 **DiPlay 零跑**。方向盘控制默认开启，升级时保留此前保存的选择。包名仍为 `com.shihab.diplay.hudtest`，同签名时可覆盖之前的测试版；原版 DiPlay 是另一个包名。
2. 关闭两个隐藏栏开关及应用管家的沉浸规则，再连接 CarPlay。
3. 断开原车与 iPhone 的蓝牙音乐连接，开始播放 CarPlay 音乐。
4. 需要排查时，先打开“记录方向盘诊断”，再播放或切换歌曲，确认上报已发送、广播监听已注册。本轮不执行 ADB 手动媒体上报。关闭记录不影响方控使用。
5. 依次按上一首、下一首和播放／暂停，观察实际效果。确认原车顶部栏、底部 Dock 均可见，点击 CarPlay 上下边缘的按钮，检查触摸是否对齐。
6. 切回原车媒体，保持 iPhone 在后台播放并切换歌曲。确认方向盘继续控制原车媒体。再在 CarPlay 明确恢复播放，确认来源 14 和方向盘控制恢复。
7. 打开设置菜单，编辑 MFI 地址或热点密码。确认输入框和滚动到底部的保存按钮不被键盘遮挡。打开安全区编辑器，确认按钮避让键盘，画布和 CarPlay 触摸尺寸保持不变。
8. 断开后重连，确认自动上报和方向盘控制可以恢复。保留诊断报告及实际效果。

如果监听已注册但计数仍为 0，需要继续查原车广播发送模块。若有广播记录但未提交，需要查 CarPlay 会话／发送入口。若已提交但没有实际切歌，需要进一步查协议发送与手机处理。
