# 零跑仪表投屏与更新渠道

本页描述 2026-10-15 新增的源码功能，尚未发布到 GitHub Release，也未安装到实车。接听和自动泊车键学习暂不包含在本次改动内。

## 仪表地图投屏（实验性）

入口：设置 → 高级 → CarPlay 仪表地图 → 零跑仪表目标屏幕。

1. 停车并打开原车的仪表投屏模式。列表只显示应用可访问的非主屏公共显示器，不预设屏幕编号 1 或 2。
2. 选择候选屏幕后显示 5 秒测试画面。只有确认测试画面位于预期的仪表投屏区域，才保存该屏幕并开启地图流。取消或显示失败不会保存。
3. 使用设置页的重连提示重新连接 CarPlay。屏幕选择不会主动中断已有连接。
4. 复用 CarPlay 独立仪表地图流和导航卡片。不会镜像主屏，也不会写入零跑原生导航提示或切换原车仪表模式。

保存的目标包括显示器编号、名称、分辨率和标志。屏幕消失、编号复用但属性改变或无法访问时停止投屏，不尝试其他屏幕。后台会话恢复保留连接时的目标；设置变化需下次连接生效。

选用零跑目标时停用 BYD 专用 ADB 投屏路由和布局判断。原有主屏 Dock、系统栏、键盘避让、触摸坐标与来源 14 方控逻辑保持不变。

普通应用无法访问的私有屏幕不在支持范围内。若列表为空或 Presentation 被拒绝，需要实车显示器权限/固件证据；本实现不自动提升权限或调用原车私有接口。

## 零跑更新渠道

- 手动检查、后台检查和 Release 页面统一指向 buluw/DiPlay；代码发布来源为 leapmotor 分支。源码已合并上游 v0.2.20；应用更新仍只使用零跑分发渠道。
- 每个 Release 只接受一个符合命名规则的零跑 APK：DiPlay-版本-leapmotor.apk，或附加八位日期的同类名称。多份匹配 APK 时不猜选。
- 支持同一 Release 中的 SHA256SUMS.txt，以及严格同名的 APK.sha256。校验内容必须包含对应 APK 文件名及 SHA-256；不能只有一个无文件名的摘要。
- 支持三段和四段版本号，按数字比较。现有 v0.2.19.1 沿用内部 0.2.19-leapmotor / versionCode 38，同一 APK 不会被反复提示更新。
- 下载后验证 SHA-256、包名、当前签名证书以及更高的 Android versionCode，随后才提供安装入口。不卸载旧版本，不清理用户数据。
- 原先缓存的上游更新会失效；下载、安装仍由用户显式启动。

后续发布需同步提高 APK 内部版本号和 versionCode，沿用 com.shihab.diplay.hudtest 包名及既有签名，上传单个零跑 APK 与对应校验文件。只修改 Release 标签而不提高 versionCode，不构成可覆盖升级的新 APK。签名轮换不在此版本支持范围内。

## 验证边界

自动化覆盖目标选择/主屏排除/屏幕移除/属性变化、更新渠道与资产筛选、四段版本/历史版本别名、旧缓存清理及安装身份规则，并生成大字体中文紧凑、中文宽屏和阿拉伯语截图。

实车仍需确认：目标确为仪表投屏区域、地图/导航卡片可显示、切换原车画面和拔断连接后恢复正常、后台恢复正常，以及同签名正式 APK 的覆盖安装。
