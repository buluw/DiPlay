# 零跑仪表投屏与更新渠道

本页描述 `v0.2.20.2` 零跑预览版的仪表投屏及更新功能。APK 内部版本为 `0.2.20.2-leapmotor`（versionCode 41），发布仓库为 `buluw/DiPlay`，详见 [发布说明](RELEASE-NOTES-0.2.20.2.md)。本版尚未安装到实车；接听和自动泊车键学习暂不包含在本次改动内。

## 仪表地图投屏（实验性）

入口：设置 → 高级 → CarPlay 仪表地图 → 零跑仪表目标屏幕。

1. 停车并打开原车的仪表投屏模式。列表只显示应用可访问的非主屏公共显示器，不预设屏幕编号 1 或 2。
2. 选择候选屏幕后显示 5 秒测试画面。只有确认测试画面位于预期的仪表投屏区域，才保存该屏幕并开启地图流。取消或显示失败不会保存。
3. 使用设置页的重连提示重新连接 CarPlay。屏幕选择不会主动中断已有连接。
4. 仪表画面来源可选 CarPlay 独立仪表地图流和导航卡片，或同步主屏视频。可校准仪表可见区域，并选择完整画面或本地裁切。不会写入零跑原生导航提示或切换原车仪表模式。

保存的目标包括显示器编号、名称、分辨率和标志。屏幕消失、编号复用但属性改变或无法访问时停止投屏，不尝试其他屏幕。后台会话恢复保留连接时的目标；设置变化需下次连接生效。

选用零跑目标时停用 BYD 专用 ADB 投屏路由和布局判断。原有主屏 Dock、系统栏、键盘避让、触摸坐标与来源 14 方控逻辑保持不变。

普通应用无法访问的私有屏幕不在支持范围内。若列表为空或 Presentation 被拒绝，需要实车显示器权限/固件证据；本实现不自动提升权限或调用原车私有接口。

## 零跑更新渠道

- 手动检查、后台检查和 Release 页面统一指向 buluw/DiPlay；代码发布来源为 leapmotor 分支。源码已合并上游 v0.2.20；应用更新仍只使用零跑分发渠道。
- 每个 Release 只接受一个符合命名规则的零跑 APK：DiPlay-版本-leapmotor.apk，或附加八位日期的同类名称。多份匹配 APK 时不猜选。
- 支持同一 Release 中的 SHA256SUMS.txt，以及严格同名的 APK.sha256。校验内容必须包含对应 APK 文件名及 SHA-256；不能只有一个无文件名的摘要。
- 支持三段和四段版本号，按数字比较。现有 v0.2.19.1 沿用内部 0.2.19-leapmotor / versionCode 38，同一 APK 不会被反复提示更新。
- 下载后验证 SHA-256、包名、当前签名证书以及更高的 Android versionCode，随后才提供安装入口。不卸载旧版本，不清理用户数据。
- 原先缓存的上游更新会失效；下载、安装仍由用户显式启动。

后续发布需同步提高 APK 内部版本号和 versionCode，沿用 com.shihab.diplay.hudtest 包名及既有签名，上传单个零跑 APK 与对应校验文件。只修改 Release 标签而不提高 versionCode，不构成可覆盖升级的新 APK。签名轮换不在此版本支持范围内。

## 验证边界

自动化覆盖目标选择/主屏排除/屏幕移除/属性变化、更新渠道与资产筛选、四段版本/历史版本别名、旧缓存清理及安装身份规则，并生成大字体中文紧凑、中文宽屏和阿拉伯语截图。

实车仍需确认：目标确为仪表投屏区域、地图/导航卡片可显示、切换原车画面和拔断连接后恢复正常、后台恢复正常，以及同签名正式 APK 的覆盖安装。

## 0.2.20.2 修正：可见区域与本地取景

实车反馈确认 HDMI display 2 的逻辑画布为 1920×720，但原车只显示右侧地图区域。0.2.20.1 按整张画布请求地图，车标和路线可能落在原车界面遮挡区；照片不足以确认导航状态本身没有传入。

根据跑跑桌面的窗口实现，为用户显式选定的 1920×720 目标增加右侧 720×720、x=1200、y=0 的默认可见区域。其他分辨率保持整屏默认；明确保存过的校准区域优先，不覆盖用户选择。没有自动选取 display 2，也没有调用 OEM 模式接口。

“仪表可见区域”提供“右侧正方形”和“整张画布”预设；停车后可拖动四条边线观察仪表校准图。保存后通过重连提示重新连接 CarPlay。默认值来自跑跑的参考布局，实际 OEM 遮罩边界仍需实车校准。

- 独立地图：按可见窗口宽高请求地图帧，放入同一窗口；未显式设置过的地图大小默认 100%，本分辨率对应请求 720×720。零跑副屏解码器使用自己的协商尺寸，不再借用主屏尺寸。原比亚迪全屏／小窗车标参数不参与零跑路由。地图和导航内容仍由手机生成。
- 同步主屏：复制已有的 CarPlay 主屏视频，不向 iPhone 声明独立仪表屏。主屏地图、导航和应用切换都来自同一条视频流；仍是单独解码输出，不承诺两块屏零延迟。这是比较和规避独立副屏兼容性问题的可选方式，不承诺高德一定提供车道级画面。
- 仪表本地取景：默认“完整画面”，保持实际解码画面的比例，必要时留黑边。“局部取景”按源画面的水平中心、垂直中心（0–100%）和放大（100–300%）进行本地裁切，仅影响仪表 TextureView。保存后重连生效。该控制不再依赖手机响应 safe area；裁切可能隐藏主屏中的转向卡或其他内容，需要按实际画面校准。
- 源画面尺寸读取 MediaCodec 输出格式，并排除合法 crop 边界内的编码补齐区域；日志保留请求尺寸、实际尺寸、编码 crop 和 stream 编号，可区分主屏 110 与仪表 111。后台仅镜像解码时，同样接收当前有效镜像的实际尺寸；已移除、替换、关闭或退出的解码器回调不更新尺寸。退出清理按实例匹配，旧镜像的迟到退出不会移除同名新镜像。
- 可见区域及来源随当前会话保留，保存新设置后需重连；屏幕丢失时停止，不切换到其他显示器。校准不抢主屏触摸或焦点。

新增回归用例覆盖默认/自定义可见区域、源裁切边界、矩阵映射、码流尺寸分离、后台会话配置快照和无效目标拒绝；截图用例增加中文紧凑/宽屏及阿拉伯语的大字体本地取景对话框。

解码尺寸回归用例另覆盖仅镜像后台输出、主屏/镜像通知去重、镜像替换/移除/关闭/退出、错误 stream、流停止后重建及 sink 关闭后的迟到通知；这些用例已随本轮完整 CI 通过。
